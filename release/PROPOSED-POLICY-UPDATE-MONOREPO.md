# Policy update for the monorepo scope

**Status: the founder's decision on this proposal was recorded on 2026-10-28 as the resolution of `PA-1` in `release/RELEASE-GATES.json`, with the clarifications in section 8. This document itself remains the proposal text; the approval record is in the gate file.** No gate status other than the `PA-1` resolution changed, and G04 stays BLOCKED. Before that resolution, `node scripts/release/check-gates.mjs --strict` treated G01, G02, G03, G05, G07, G09, G11, G12 and PC-1 as not satisfied for `public-source-release`. A clean dependency report or `npm audit` is not a legal-compatibility finding.

## 1. What changed in scope

The approvals recorded on 2026-10-28 covered the MVP-1 source tree (Rust contracts, TypeScript SDK, plain-DOM Console, docs, CI, release controls). The monorepo adds:

- `apps/landing`: the landing page, imported with its own LICENSE, NOTICE, brand assets and 44 commits of history;
- `apps/web-console`: a Next.js console;
- a root npm workspace with 444 third-party packages (previously 3).

## 2. Proposed source-publication scope (decision needed)

The gate file defines four targets. This proposal concerns only the first public one and keeps the others separate:

| Target (as defined in the gate file) | What it is | Covered by this proposal? |
|---|---|---|
| `private-remote-backup` | push of the branch to a verified private remote | no change proposed |
| `public-source-release` | making the source repository public: experimental, source-only | **yes: the scope below** |
| `versioned-release` | a tagged or versioned release with artifacts (binaries, Wasm, packages, container images) | **no**: keeps its full requirements (including G04, G10 and E01 to E05) and needs fresh approvals |
| `production` | production or real-value deployment (including hosted sites run for real use) | **no**: not intended by this project today |

Wording of the PC-1 extension to the whole monorepo (recorded as amendment `PC-1-A1` in the gate file): *source, lockfiles and documentation only. No binaries, Wasm releases, container images, packages, deployed or hosted sites are published or authorized, and nothing here is production-ready.*

Limits of this scope, to be stated with it:

- A source-only scope does not itself establish legal compatibility and does not authorize any release or push.
- Every file in the tree needs redistribution rights to be published, not only the code. A notice that reserves brand rights (such as `apps/landing/NOTICE`) restricts reuse; it does not establish permission to redistribute an asset. The Aalto Display-derived artwork (section 5) has been excluded from the publication candidate because no permission is held; the remaining assets are not thereby cleared.
- Deploying the landing page or the web console anywhere is a separate decision (see the LGPL-labelled optional packages in section 3).

## 5. Artwork licensing note (unresolved)

Details, file inventory with hashes and options: `release/ARTWORK-REMEDIATION-PLAN.md`.

- `apps/landing/brand-pack/README.md` says the outlined wordmarks, social images and favicons use Aalto Display, "a personal-use font". `NOTICE` and `LICENSE` say nothing about it. No repository document establishes permission to redistribute the font or artwork derived from it; no font file has ever been in the landing history.
- On individual inspection, 20 files carry the wordmark (the four lockup SVGs, the two logo PNGs and the four social PNGs, each in `apps/landing/brand-pack` and as an identical copy under `apps/landing/public/brand`). The favicons, app icons and avatars viewed are symbol-only; the README's grouping of favicons with the wordmark artwork is broader than what was observed.
- `src/app/opengraph-image.png` already shows a monospace wordmark (commit `f2eee53`).
- The `brand-pack` files carry content-credential metadata saying Claude provided the file at a user's request and may have created or modified it. That describes handling, not licence or authorship of the outlines.
- **Founder statement:** the founder has confirmed that no licence permitting redistribution of Aalto Display-derived artwork is held. The 20 wordmark files were therefore excluded from the tree and from the unpublished landing history that this branch carries (Option B; old and new commit hashes are in the plan). The original share images in that history were repointed to the existing JetBrains Mono versions. No replacement wordmark was produced and no font was downloaded; the new wordmark is a redesign task.
- **Still not cleared:** nothing here states that any remaining file is cleared for redistribution. The symbol, icon and avatar files are of unrecorded authorship and licence, and the JetBrains Mono wordmark images have only the repository's own statement behind their font licence. The separate public `tobin-landing` repository still contains the original files and was not changed.
- **Open founder choice:** a short written statement of the symbol's authorship and licence, and the later redesign.

## 6. Public history and author metadata

The founder's personal email address appears as author and committer in all 44 landing commits (and in 89 commits repository-wide), as commit metadata only. A scan of the landing tree and history found no occurrence in file contents, no local user paths, and no secret-like strings. **The founder has directed that the imported Git history and the original author and committer metadata be preserved as-is.** That direction is not authorization to publish.
