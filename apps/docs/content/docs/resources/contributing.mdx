The authoritative rulebook is
[`CONTRIBUTING.md`](https://github.com/tobin-protocol/tobin/blob/main/CONTRIBUTING.md). Read it before opening a pull
request. The [Code of Conduct](https://github.com/tobin-protocol/tobin/blob/main/CODE_OF_CONDUCT.md) applies to all
participation.

## Ways to contribute

- Report a bug or propose a feature with the repository's issue forms.
- Improve documentation: this site, the README, or a code comment that has become untrue.
- Fix a bug or add tests.
- Review pull requests.

Vulnerabilities go through the [security policy](/docs/resources/security), never a public issue.

## Before you start

1. Read [Project status](/docs/introduction/project-status) so your change fits the current scope.
2. Read the [invariants](/docs/concepts/invariants). A change that weakens one will not be accepted.
3. Open an issue first for anything larger than a small fix.

## Workflow in one paragraph

Fork the repository and work in your fork. Branch from your fork's up-to-date `main` as `<type>/<short-description>`, commit with Conventional Commits, run the relevant tests, and open a
pull request using the template. State every skipped check. See [Contribution workflow](/docs/development/workflow).

## Documentation changes

Docs live in two places and follow different rules. See
[Documentation governance](/docs/resources/documentation-governance) and
[Writing documentation](/docs/resources/writing-docs).

## AI-assisted contributions

You are responsible for everything you submit, including output produced with an AI tool. Do not add AI attribution or
co-author trailers to commits. AI coding agents must follow
[`AGENTS.md`](https://github.com/tobin-protocol/tobin/blob/main/AGENTS.md).

## Not available

GitHub Discussions are not enabled. Use issues for questions that are not sensitive. Conduct concerns go privately to
the project maintainer, as described in the
[Code of Conduct](https://github.com/tobin-protocol/tobin/blob/main/CODE_OF_CONDUCT.md); there is no moderation team.
