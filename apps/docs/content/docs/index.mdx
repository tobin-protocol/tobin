the system is built, how to run and change it, and what each part does and does not guarantee.

## Two kinds of documentation

This site is the **maintained developer documentation**: it is edited as the code changes. The repository also holds
**canonical engineering records** in the root `docs/` directory: milestone acceptance and closure documents, audits,
security reviews, threat models, Testnet evidence and the contract reference. Those records are historical and are
not copied or rewritten here. Where a page depends on one, it links to the record on GitHub.

See [Documentation governance](/docs/resources/documentation-governance) for the rule of thumb and
[Writing documentation](/docs/resources/writing-docs) if you want to add a page.

## What these docs do not claim

- No independent audit has been performed. The reviews in the repository are the implementing author's own.
- Testnet runs were a single, owner-run exercise with test assets. They show the mechanics work, not that the
  system is ready for real value.
- There is no published HTTP API reference for the institutional application and no OpenAPI description. The
  [HTTP routes](/docs/reference/http-routes) page says what exists and where to read it.
