# D. Security audit report

Scope: contracts (source review of `contracts/clearing/src/lib.rs`, `contracts/token/src/lib.rs`), SDK, sandbox and W0/W1 console, signer boundaries, deployment evidence. Method: source reading, existing tests, CI logs, `npm audit --omit=dev` (0 vulnerabilities), read-only Testnet queries. No exploitation, no transactions. **This is an internal review by the same party that built the system, not a formal security audit and not independent.** Passing automated tests does not constitute an audit.

"Blocks MVP" = blocks a credible Testnet demonstration. "Blocks SCF" = blocks a credible submission.

| ID | Sev | Finding | Location and evidence | Impact | Recommendation | Blocks |
|---|---|---|---|---|---|---|
| D-01 | Critical (for a public app) | No authentication, authorization or organization isolation exists beyond the W0 development identity provider | no auth code in `apps/`; `lib/w0/identity.ts` is fixed dev accounts without credentials | a deployed application would have no access control; organization isolation untestable | decide the identity provider; build server-side authorization with isolation tests before any public deployment | MVP, SCF |
| D-02 | High | Wallet signing path unvalidated and unimplemented | no wallet dependency; tests T3 to T14 not run (`phase-2c/wallet-validation-results.md`); `NetworkTransportNotAuthorized` | cannot claim wallet compatibility or authorize contract calls from a browser | authorize and run attended validation first | MVP, SCF |
| D-03 | High | Signature-expiry policy (10 ledgers, about 50 s) vs asynchronous multi-organization signing | `join_session` needs creator and joiner; `settle` needs every debtor, all signing entries for one transaction; policy W3 unresolved; EQ-20 | a naive flow would fail on timing or tempt an unsafe longer window | design a synchronous "signing room" or decide a longer, bounded Testnet window; record the decision | MVP |
| D-04 | High | B2: bare `powershell.exe` and `icacls` invocation and inherited environment in the signer (3 sites) | `scripts/tst-signer/signer/dpapi-key.cjs`, `state-store.cjs`; `PROCESS-INVOCATION-HAZARD.md` | blocks any signer execution; does not affect contracts or the clearing demo | keep deferred; use the governed multisig tooling for minting in the demo; do not ship the signer path | no (if signer excluded) |
| D-05 | Medium | Immutable clearing contract: no admin, upgrade, abort, timeout, cancel or amend; hard ceilings 4/16/16 | `lib.rs` header and constants `PARTICIPANT_CEILING` etc. | any defect cannot be patched; a participant can stall a session forever; demo scale capped | accept for MVP and state it; a v2 contract would be a new deployment and a decision | no (state clearly) |
| D-06 | Medium | Storage lifetime handled by provisional unmeasured constants; no automatic TTL maintenance | `LIFETIME_THRESHOLD/EXTEND` in `lib.rs`; instances live ~900k ledgers (about 50 days) when queried | session data and instances can be archived; Testnet resets | schedule extension operations and monitor TTL; document restore procedure | MVP (operations) |
| D-07 | Medium | Any contract-kind token may be named in a session (no allow-list) | `MVP-1-ABI-AND-AUTHORIZATION-REFERENCE.md` line 9; `settle` calls `token.transfer` | a hostile token can fail or grief settlement; state is written before transfers and reentrancy into the same contract is not expected under Soroban host rules (not independently tested here) | restrict to known tokens at the application level; test a hostile-token contract in the host | no |
| D-08 | Medium | Caller-chosen session ids can be squatted | `create_session(session_id)`, `SessionExists`; console derives ids from labels | griefing and collisions | registry generates random 32-byte ids; never derive from guessable labels | no |
| D-09 | Medium | Signed authorization entries of a failed transaction stay reusable until expiry (accepted behaviour EQ-20) | `phase-2c/authorization-security-findings.md` | replay window equals expiry | keep expiry minimal; fresh authorization after any failure | no |
| D-10 | Medium | Governance is not independent: all three admin signers are one person; master key still enabled at weight 1 | `accounts/testnet-admin.json`; Horizon query: thresholds 5/6/7, weights 5, 2, 1, master 1 | marketing as "multi-party governance" would be false | state plainly; consider enlisting real co-signers and disabling the master key (owner decision) | SCF (claims) |
| D-11 | Medium | Headline Testnet lifecycle evidence is unpublished | README sections on MVP-1; manifest `functionalChecks` has only `mintTx` and `createSessionTx` | reviewers cannot verify | produce a fresh, public, reproducible Testnet run | SCF |
| D-12 | Medium | Deploying `apps/web-console` as is would publish the sandbox API and the W0 console | `/api/rpc`, `/api/bootstrap`, `/api/w0/*`, development identity enabled by `W0_ALLOW_DEV_IDP=1` | exposure of non-production surfaces | build the product app as separate routes/project; keep W0 off the public host | MVP |
| D-13 | Low | Manifest inconsistency: rejected tests B and C list the success hash of test A | `contracts/deployments/testnet.json` versus `docs/governance/governed-token-evidence.md` | evidence confusion | correct with owner approval | no |
| D-14 | Low | Any admitted participant can finalize or propose; creator authorization needed for every join | `lib.rs` | proposals can stall but cannot move value without all approvals; creator is a trust point | document; acceptable for MVP | no |
| D-15 | Low | Public-path exposure of an account name in archived evidence | `phase-2c/PUBLIC-PATH-EXPOSURE-REVIEW.md` | privacy | owner decision outstanding | no |
| D-16 | Info | Tests ran on Soroban host 29; Testnet reported protocol 30 | read-only `getLatestLedger` | untested behavioural drift | re-run Testnet functional checks on the current protocol | MVP (verification) |
| D-17 | Info | Good controls found: checked arithmetic, `require_auth` placement, per-debtor `require_auth_for_args`, state-before-transfer atomicity, closed shapes, CSP and security headers, CSRF, rate limits, SHA-pinned CI actions, zero production dependency vulnerabilities | source and CI | | keep | — |
