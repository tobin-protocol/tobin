## 4. Canonical hashing procedure (Recommendation, implemented and tested as a hash-only tool)

Tool: `compute-baseline-hash.cjs` (copy: `compute-baseline-hash.cjs.txt`). It reads files and prints hashes; it has no process, network or dynamic-code API (a test asserts this) and cannot sign or run the signer.

1. **Exact inputs.** (a) The seven closure files read from the signer directory: `authorization.cjs`, `dpapi-key.cjs`, `refusal.cjs`, `sdk-loader.cjs`, `state-store.cjs`, `tst-signer-core.cjs`, `tst-signer.cjs`; (b) `deployment-config.json`, or the word `ABSENT`; (c) the pinned SDK identity: `package.json` and `dist/stellar-sdk.js` of `@stellar/stellar-sdk` 17.4.0.
2. **Byte rules.** Each input is hashed with SHA-256 over its raw bytes; no newline conversion is ever applied. Inputs (a) and (b) are **refused** if they contain a CR byte, start with a UTF-8 BOM or are not valid UTF-8, so checkout line-ending settings cannot change the hash (all current files are LF-only, no BOM: Verified). Inputs (c) are hashed exactly as stored.
3. **Manifest.** UTF-8 text, LF line endings: the header `TOBIN-TST-SIGNER-BASELINE v1`, then one line `<sha256>  <label>` per input (two spaces), labels `file:<name>`, `config:deployment-config.json`, `external:@stellar/stellar-sdk@17.4.0/package.json` and `.../dist/stellar-sdk.js`, **sorted in ordinal (byte) order**, ending with a final LF.
4. **Hash.** The baseline hash is the SHA-256 of the manifest bytes. With the configuration `ABSENT` it is the **code baseline B0**; with `deployment-config.json` present it is the **full pin P**.
5. **Closure guard.** The tool computes the real `require` graph of `tst-signer.cjs` and **refuses** if it differs from the approved list, so a new module cannot slip in unhashed.
6. **Excluded, with reasons.** `pinned.cjs` (it carries the pin: circular, and superseded by the independent mechanism); `make-deployment-config.cjs` (not loaded when signing; its output is covered by the config hash); tests, mutation tools, evidence scripts (not runtime); the state file, logs, the DPAPI file and any secret; every environment-specific value (`LOCALAPPDATA`, `PATH`, user, clock) and runtime or transaction data.

## 6. Proposed independent pin mechanism (Recommendation; NOT implemented)

### 6.1 What cannot be solved inside the signer

No check inside the signer can defend against someone who can edit the signer: they can remove the check. So the verifier must be **outside the thing it verifies**: either a human with a separate record, or a tool run from a location the attacker cannot write. The design therefore has two parts that must both be present.

### 6.2 Part A (mandatory, outside the signer): verify before every session

Before each session the operator runs the hash-only tool **from a separately held, read-only copy** (a fresh extraction of the reviewed git tag into an empty directory, or an Administrator-owned folder) against the signer directory, with the approved hash typed from the independent record:

`node compute-baseline-hash.cjs --signer-dir <signer dir> [--config <deployment-config.json>] --verify <approved hash>`

Only `VERIFY: MATCH` (exit 0) allows the session to continue. Every other outcome, including a missing or malformed hash, a mismatch, an unreadable or CRLF file, or a changed closure, means do not run.

### 6.3 Part B (smallest in-signer change): the signer refuses to run unless it matches an approved hash it did not store

Design (about 30 lines plus tests; to be implemented only after you approve it):

1. A small module `baseline.cjs` (same procedure as the tool; it becomes part of the hashed closure) computes the baseline hash over the files the signer actually loads, the SDK identity and `deployment-config.json`.
2. `tst-signer.cjs` calls it **before** `init`, `reconcile`, `prepare`, key loading or any network access in `execute`. `preview` may run unpinned and prints the computed hash for comparison.
3. **Supply channel: the approved hash is typed (or pasted) by the operator at the prompt** from a record kept outside the signer directory and outside the signer's reach (repository remote through a pull request, plus a second medium such as another device or paper). It is not read from any file in the signer directory and is not stored. Rejected: an empty answer, anything that is not exactly 64 lowercase hex characters, and any value that differs from the computed hash (constant-time comparison).
4. **Fails closed:** a missing, malformed or mismatching value, an unreadable or CR/BOM file, a changed closure, a missing deployment configuration, or any exception in the computation ends in a refusal with exit code 1 and nothing else happens (no key, no network, no state change).
5. `pinned.cjs` is no longer trusted for execution; it can stay `null` or be removed from the closure. The existing `deployment-config.json` hash check can remain as a harmless extra.
6. Optional second channel for later (not recommended first): an approved-hash file under `%ProgramData%\TobinSigner\` writable only by Administrators, whose ACL the signer inspects (as it already does for the state file) before trusting the content. It removes the typing but depends on the operator not running as an administrator.

### 6.4 Trust boundary

| Asset | Who can change it | What detects a change |
|---|---|---|
| Approved hash record | the founder and the independent reviewer (repository pull request; second medium) | nothing inside the signer directory can alter it |
| Signer sources, `deployment-config.json`, `pinned.cjs`, SDK files | anyone who can write the operator's user profile or the signer directory | Part B for edits to anything that is hashed; Part A for edits to the signer itself, run from a trusted copy |
| Hash tool used in Part A | whoever controls the separate copy | its own hash is recorded with the approved hash; run it from a fresh git extraction |
| `LOCALAPPDATA`, `PATH` | the process environment | not covered; see 6.5 |

| Scenario | In-signer check (B) | External verification (A) |
|---|---|---|
| A recipient, amount, Wasm hash, ceiling or expectation constant is edited | detected (different hash) | detected |
| `deployment-config.json` swapped for another identity | detected | detected |
| `pinned.cjs` rewritten to match a swapped config | irrelevant (not trusted) | irrelevant |
| SDK bundle or `sdk-loader.cjs` replaced | detected (the bundle hash is a manifest line; the loader is hashed) | detected |
| The signer is edited to skip the check | **not detected** | **detected**, if run from a trusted copy |
| Whole signer directory replaced with a malicious one | not detected | detected by Part A only |
| Wrong value typed or recorded | refuses (safe) | refuses (safe) |
| A bad configuration was approved by mistake | not detected: this is a review failure | same |
| `LOCALAPPDATA` / `PATH` altered | not detected | not detected |
