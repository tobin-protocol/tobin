# AST allowlist specification (Revision 6.3 CANDIDATE, NOT APPROVED)

The authority is the code in `ast-policy.cjs` (tables `ALLOWED_NODE_TYPES`, `BLOCKED_NAMES`, `APPROVED_REQUIRES`, `APPROVED_EXEC`, `APPROVED_COMPUTED_EXPLICIT`, `SDK_LOADER_PATTERNS`, `SAFE_NAMESPACES`, `SAFE_CALLABLES`, `MODULE_MEMBERS`). This document explains them. The analyzer accepts a deliberately narrow language: **the syntax that the eight reviewed runtime files use, and nothing else.** It is not a general JavaScript scanner and it does not try to recognise every malicious program.

## 1. Node types

### Accepted (41 types including `Program`, each present in at least one of the eight files)

`Program`, `ExpressionStatement`, `BlockStatement`, `VariableDeclaration`, `VariableDeclarator`, `FunctionDeclaration`, `FunctionExpression`, `ArrowFunctionExpression`, `ReturnStatement`, `IfStatement`, `ForStatement`, `ForOfStatement`, `SwitchStatement`, `SwitchCase`, `TryStatement`, `CatchClause`, `ThrowStatement`, `ClassDeclaration`, `ClassBody`, `Identifier`, `Literal`, `TemplateLiteral`, `TemplateElement`, `ArrayExpression`, `ObjectExpression`, `Property`, `ArrayPattern`, `ObjectPattern`, `AssignmentPattern`, `RestElement`, `SpreadElement`, `CallExpression`, `NewExpression`, `MemberExpression`, `AssignmentExpression`, `UpdateExpression`, `UnaryExpression`, `BinaryExpression`, `LogicalExpression`, `ConditionalExpression`, `AwaitExpression`.

The census of the eight files (generated by `inventory-report.cjs`, `inventory-eight-files.md`) shows each of these occurs; nothing else occurs.

### Refused by node type (rule `A1`), with the reason none is needed

| Node type | Why refused |
|---|---|
| `ImportExpression` | dynamic `import()` loads arbitrary modules; the files use none |
| `ChainExpression` | optional chaining (`a?.b`, `a?.()`); makes provenance reasoning harder; unused |
| `SequenceExpression` | `(0, fn)(…)` is the classic way to detach a callee from its receiver; unused |
| `TaggedTemplateExpression` | a tagged template is a hidden function call; unused |
| `ThisExpression`, `Super`, `MetaProperty` | not used; `this` would give an alias of whatever called the function |
| `YieldExpression`, generators, `for await` | unused |
| `WithStatement`, `LabeledStatement`, `While`/`DoWhile`/`ForIn`, `Break`/`Continue` | unused; `with` also changes name resolution |
| `ClassExpression`, `MethodDefinition`, `PropertyDefinition`, `StaticBlock` | the only class is `class StateError extends Error {}` with an empty body |
| `DebuggerStatement`, `EmptyStatement`, `ExportNamedDeclaration`, import declarations | unused (imports are also syntax errors in script mode) |

Additional syntactic limits (rules `A1`, `N1`): classes must extend `Error` and have an empty body; unary operators are limited to `! typeof - + void`; object properties must be `init` properties (no getters or setters) and may not have computed keys; patterns must be identifiers, object/array patterns, rest, or assignment patterns.

Regular-expression literals are allowed (`authorization.cjs`, `refusal.cjs`, `state-store.cjs`, `tst-signer-core.cjs` use them for input validation); a regex literal is a value with no power to call anything.

## 2. Module loading (`require`)

`require` must be a free (unshadowed) identifier used **only** as `const <binding> = require("<string literal>");` as a direct top-level statement. Anything else (call with a variable, template, two arguments, inside a function, aliased, passed, returned, a property of something) is rule `R1`.

The approved specifiers are per file (table `APPROVED_REQUIRES`); each may appear **once** (`D1` for a repeat).

| File | Built-ins (form) | Local |
|---|---|---|
| authorization.cjs | none | `./refusal.cjs` |
| dpapi-key.cjs | `child_process` as `{ execFileSync }` only | `./refusal.cjs` |
| pinned.cjs, refusal.cjs | none | none |
| sdk-loader.cjs | `fs`, `path`, `crypto`, `vm` as whole-module bindings | none |
| state-store.cjs | `fs`, `crypto`, `path` whole; `child_process` as `{ execFileSync }` only | none |
| tst-signer-core.cjs | `crypto` whole | `./refusal.cjs`, `./authorization.cjs` |
| tst-signer.cjs | `fs`, `path`, `readline` whole | `./sdk-loader.cjs`, `./tst-signer-core.cjs`, `./dpapi-key.cjs`, `./state-store.cjs`, `./pinned.cjs` |

Approval is **by structure and binding identity, not by string match**: the string `"child_process"` appearing is not what grants anything; it is the exact declarator shape plus the per-file entry. Even when the require form is refused, the declared binding is still tracked as a capability so later rules also fire independently (found while testing: mutant T18).

Not allowed anywhere: `require.resolve`, `require.main`, `module.require`, `createRequire`, `import()`, `process.getBuiltinModule`, `process.binding`, `process.mainModule`, `Module`.

## 3. `module`, `exports`, `__dirname`

`module` is accepted only in the single top-level statement `module.exports = { ... };` (`M1`). `exports` appears only as the property name in that statement. `__dirname` is a plain value.

## 4. Free (global) identifiers

Any identifier not declared in the file is "free". Only these are accepted, each in a constrained position (`G1` otherwise):

* namespaces called through an approved member: `Object.{keys,entries,freeze}`, `JSON.{parse,stringify}`, `Math.floor`, `Number.{isFinite,isInteger}`, `Buffer.{from,isBuffer}`, `Array.isArray`, `Date.{now,parse}`, `console.{log,error}`;
* callables used as call, `new`, or `instanceof` operand: `Number String BigInt Boolean Symbol Uint8Array Set Promise Error Date isFinite setTimeout`; `Error` also as a class `extends` target;
* values `undefined NaN Infinity __dirname`;
* `process` and `globalThis` under their own rules (below).

Every other free identifier is refused, including `eval`, `Function`, `Reflect`, `Proxy`, `global`, `self`, `window`, `frames`, `require` (other than as above), `module` (other than above), and any unknown name. A free identifier of unknown origin is **never** assumed harmless.

Declaring (shadowing) any reserved or safe-global name (`process`, `require`, `module`, `exports`, `globalThis`, `Object`, `JSON`, …) is `S1`. This closes the "shadowed identifier" route: a local named `process` could otherwise hide the rules that key on the global `process`.

## 5. `process`

Only `process.<member>` with a non-computed member. Members and their only accepted positions:

| Member | Accepted position |
|---|---|
| `env` | see the environment inventory: `process.env.NAME` read; `...env` spread into an options object; value of an `env` option property; default value of a parameter; operand of `||` in one of those positions |
| `argv` | `process.argv.slice(...)` |
| `exit` | called directly |
| `platform` | default value of a parameter, or an operand of a binary expression |
| `stdin`, `stdout` | the value of a property of the object literal passed to `readline.createInterface` |

Everything else about `process` (`process` as a value, destructuring, `process[k]`, `process.binding`, `process.mainModule`, `process.getBuiltinModule`, unlisted members, `process` passed or returned) is refused (`C1`).

## 6. The SDK-loader exception (patterns P_CONST, P_BUNDLE, P_SHA, P_CHECK, G1, V2, G2, G3)

The Revision 6.2 exception for `globalThis` and `vm` in `sdk-loader.cjs` is preserved **only** as eight exact statements, each compared as a whole AST (position-free JSON of the node) against a reference parsed from a constant string:

```
P_CONST  const EXPECTED_BUNDLE_SHA256 = 'de18071d…9b92f';                       (program level)
P_BUNDLE const bundle = fs.readFileSync(path.join(packageDir, 'dist', 'stellar-sdk.js'));
P_SHA    const sha = crypto.createHash('sha256').update(bundle).digest('hex');
P_CHECK  if (sha !== EXPECTED_BUNDLE_SHA256) throw new Error('SDK bundle hash mismatch: refusing to load');
G1       globalThis.self = globalThis;
V2       vm.runInThisContext(bundle.toString('utf8'));
G2       if (!globalThis.StellarSdk) throw new Error('SDK bundle did not initialise');
G3       return globalThis.StellarSdk;
```

Each must occur **exactly once**, as a direct statement of `loadSdk` (P_CONST at program level), **in that order** (`T1`). Inside them the analyzer also checks **binding identity**: `fs`, `path`, `crypto`, `vm` must resolve to the corresponding `require('…')` bindings; `bundle` must resolve to the `const` declared by P_BUNDLE; `globalThis` must be the unshadowed global. Because P_SHA hashes the same `bundle` that V2 executes, and P_CHECK precedes V2, the exception proves that the bytes run are the bytes whose SHA-256 was compared with the pinned value. This is a strictly **narrower** exception than Revision 6.2's token patterns: the 6.2 patterns did not check the order, the hash comparison or the identity of `bundle`.

The exception is not widened: any other `globalThis`, `vm`, `self`, `runInThisContext`, `runInNewContext`, `createContext`, or a changed pinned hash, argument, path or ordering is refused (tests and mutants D-group).

## 7. Computed member access

Computed access is where a name is chosen at run time, so it is the most restricted construct.

* Never on a capability binding, a free identifier, or a value reached from `process` (`K1`).
* Never as a call target, a `new` target, or an assignment target (`K1`).
* Object literals may not have computed keys.
* Allowed only when the **key's origin is bounded** (`bounded-key`): a numeric literal; a non-blocked string literal (equivalent to `a.b`); a `for (let i = 0; …; i++)` index; the variable of `for (const k of Object.keys(x))`, `Object.keys(x).sort()` (directly or through a `const`), `Object.entries(x)` (the key slot of `[k, v]`), or an array literal of non-blocked strings; or the index parameter (2nd) of an arrow/function passed directly to `.forEach`/`.map`.
* One explicit exception, `cfg.resourceLimits[opName]` in `tst-signer-core.cjs`, by exact source text and count. See the capability specification, "Known residuals".

A key that came from the environment, from `process.argv`, from a function return, or from an unresolved parameter is **not** a bounded origin and is refused.

## 8. Blocked names

A fixed set of names (`BLOCKED_NAMES`) is refused as a non-computed property name, an object key, a string literal, or template text: `process require module exports globalThis global self window frames vm eval Function Reflect Proxy constructor __proto__ prototype getPrototypeOf setPrototypeOf defineProperty defineProperties getOwnPropertyDescriptor(s) getOwnPropertyNames create getBuiltinModule binding mainModule dlopen createRequire runInThisContext runInNewContext runInContext createContext compileFunction Script apply bind import child_process exec execSync execFile spawn spawnSync fork Worker WebAssembly …`. This is **defence in depth only**: the primary protection is that the sensitive objects cannot be obtained as values at all. `.call` is deliberately *not* blocked because the SDK's `Contract.call` is used by `tst-signer-core.cjs` and `tst-signer.cjs`; `execFileSync.call(...)` is refused anyway because a capability cannot be the object of a member access.

Exceptions to the name block are exact: the property `exports` of `module.exports = …`; the pattern-covered `self` (G1) and `runInThisContext` (V2) tokens; the local parameter/option named `exec` (it is the approved alias of `execFileSync`, see the process-execution inventory).

Identifiers must be plain ASCII (`N2`), which keeps the old homoglyph protection; non-ASCII text inside string literals is allowed.
